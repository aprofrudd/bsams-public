# Technical Decisions

1. **Dynamic Z-scores:** Calculate on-read, not stored in database
2. **Metric-agnostic design:** JSONB metrics column avoids schema migrations for new test types
3. **Auth:** Supabase Auth with JWT in HttpOnly cookies. Tests use dependency override (`app.dependency_overrides[get_current_user]`)
4. **Date parsing:** Strictly DD/MM/YYYY format
5. **Auto-create athletes:** CSV upload auto-creates athlete records when names not found in DB
6. **Trailing slash proxy:** `skipTrailingSlashRedirect: true` + regex rewrite in next.config.js to prevent Vercel/FastAPI redirect loops
7. **Rate limiting:** slowapi middleware (5/min auth, 10/min uploads, 30/min admin, 60/min general). `/auth/login` is 30/min because every BSAMS user reaches the API from the same proxy address — six station iPads signing in would otherwise share one 5/min bucket with the rest of the product. Brute-force is guarded per-account by the email-keyed `_check_lockout`, not per-address. Public combine routes are 1200/min keyed on the share token (every device showing the board is one apparent address, and 304s count)
8. **CSV limits:** 10MB file size, 10,000 row maximum
9. **Batch inserts:** CSV events inserted in single bulk operation with individual fallback
10. **Multi-metric dashboard:** MetricSelector reads available metrics dynamically from backend, refreshes via `dataVersion` counter after data mutations
11. **Benchmarks for all reference groups:** PerformanceGraph passes athlete gender and computed mass band to benchmarks API
12. **Split event/benchmark loading:** Events reload on athlete/metric change; benchmarks reload on reference group change; date toggles persist across reference group switches
13. **On-demand radar:** ZScoreRadar only mounts when user clicks "Generate Radar Plot"
14. **Inline CRUD:** Add/edit/delete events via modal from PerformanceTable; edit athlete profile (name/gender/DOB) from AthleteSelector
15. **Auto-calculated metrics:** EUR = CMJ Height - SJ Height; RSI = Flight Time / Contact Time (computed on save, not manual input)
16. **Radar date selection:** ZScoreRadar fetches all events, date dropdown selects primary event, composite metric picker fills missing metrics from other dates
17. **Radar zone bands:** 4 background Radar elements with colored fills (green/cyan/yellow/red) at Z=3/1/0/-1 for visual zones
18. **Radar dot colors:** Dots color-coded by Z-score (green>=1, cyan>=0, yellow>=-1, red<-1) with white stroke ring; dashed ring on override-sourced dots
19. **Service role key:** Backend MUST use Supabase service_role key (not anon) to bypass RLS for server-side queries
20. **Auto-profile creation:** Profiles created on signup/login via select+insert (never upsert, to avoid overwriting admin roles)
21. **Admin data filtering:** Shared data view filters consents in Python (not DB) and excludes admin accounts from results
22. **Metrics validation on input only:** `validate_metrics()` checks allowed keys, numeric types, and ranges on `PerformanceEventCreate`/`Update` — NOT on `Response` (DB may contain legacy keys)
23. **Error sanitization:** Global exception handler returns generic 500 in production, detailed errors in development. `ENVIRONMENT` config var controls behavior.
24. **Request logging:** Middleware logs method, path, status code, and duration (ms) for every request. `LOG_LEVEL` config var controls verbosity.
25. **DB health check:** `/health` endpoint pings Supabase with a simple query, returns 503 if unreachable
26. **Sync endpoints:** All non-auth router endpoints use `def` (not `async def`) so FastAPI runs them in threadpool — avoids blocking event loop with sync Supabase client. Auth endpoints kept `async` for rate limiter compatibility.
27. **Multi-worker:** Procfile uses `--workers ${WEB_CONCURRENCY:-2}` for concurrent request handling
28. **Focus trapping:** All modals use `useFocusTrap` hook for accessibility (Tab/Shift+Tab cycling, Escape to close, focus restore)
29. **Pinned dependencies:** `requirements.txt` uses exact versions (e.g., `fastapi==0.128.2`) to prevent breaking changes
30. **Admin N+1 fix:** Shared athletes endpoint uses single `.in_()` query instead of per-coach `.eq()` loop
31. **Route restructure:** Dashboard renamed to Testing, new Training section. Root `/` redirects to `/testing`
32. **Shared athlete context:** `AthleteContext` provides `selectedAthlete` across Testing and Training pages
33. **Training sessions:** Session logging with RPE, duration, computed sRPE (generated column). Free-text training types
34. **Wellness questionnaire:** 5 scores (1-5) with UNIQUE(athlete_id, entry_date). 409 on duplicate date
35. **Training load analysis:** TrainingLoadEngine calculates daily load, weekly load, monotony, strain, ACWR from sRPE data
36. **Readiness indicator:** Traffic light combining ACWR zones + latest wellness scores (inverts fatigue/soreness/stress)
37. **Exercise prescriptions:** Nested under training sessions (FK with CASCADE). Sets, reps, weight, rest, duration, distance. Conditioning fields: intensity_type (rpe/speed_kmh/power_watts), intensity_value, rest_between_reps_seconds
38. **Metric registry:** Central source of truth for metric definitions (`metric_registry.py` backend, `metricRegistry.ts` frontend). Replaces scattered METRIC_LABELS/ALLOWED_METRIC_KEYS
39. **Data-driven navigation:** `NAV_ITEMS` array in AppHeader with `matchPaths` for active state. Adding sections requires no component changes
40. **Exercise library:** Coach-level reusable exercise database with UNIQUE(coach_id, exercise_name). CRUD with ILIKE search and category filter. Defaults pre-fill when selecting from autocomplete
41. **Exercise autocomplete:** Client-side combobox loads full library on first focus (<200 items), filters locally. Keyboard nav (arrows/enter/escape). Selecting pre-fills name, category, reps, weight, rest, intensity defaults, duration
42. **Session templates:** Reusable session plans with nested exercises. Replace-all semantics on exercise updates (delete all, re-insert). Template apply expands sets (sets:3 -> 3 prescription rows)
43. **Template exercises soft reference:** `exercise_library_id` uses ON DELETE SET NULL — template survives library deletions, exercise_name stored independently
44. **VBT load-velocity profiling:** Dedicated `vbt_profiles` + `vbt_sets` tables (not JSONB metrics). Linear regression calculated on-read, not stored. MVT defaults per exercise with optional override
45. **VBT peak velocity fallback:** Analysis uses mean_velocity_ms, falls back to peak_velocity_ms when mean is null. Applies to both backend engine and frontend chart
46. **VBT client-side calculator:** Bidirectional velocity<->load prediction runs client-side from regression coefficients (no API call needed). Server-side predict endpoint also available
47. **VBT chart scaling:** Y-axis scales to actual data point velocities, not regression intercept (which can be much higher at zero load)
48. **Mobility assessments:** NASM-style movement screening (overhead squat, single leg squat L/R). Findings stored as JSONB with nested region->compensation->{observed, severity, side} structure. Assessment types validated in router (not DB enum)
49. **Assessment photo storage:** Photos stored in Supabase Storage private bucket (`assessment-photos`), signed URLs generated on-read (1-hour expiry). Path: `{coach_id}/{athlete_id}/{assessment_id}/{view_type}_{timestamp}.ext`. 10MB file size limit
50. **Auto-generated summary:** Client-side summary generation from checklist findings. Stored in `summary` column for quick display without parsing JSONB
51. **Lactate profiling:** Dedicated `lactate_tests` + `lactate_stages` tables with piecewise 3-segment regression for LT1/LT2 auto-detection. Client-side TypeScript port in `lactateAnalysis.ts` mirrors backend engine
52. **Lactate threshold flow:** Form captures raw stage data only (no threshold inputs). Thresholds set post-chart in expanded view via Auto-Detect button + editable LT1/LT2 inputs + Save Thresholds. Uses existing PATCH endpoint for partial updates
53. **Lactate chart line graphs:** ComposedChart with Line components (monotone curves) connecting scatter dots for both lactate (cyan) and HR (amber), rendered before Scatter so dots appear on top
54. **Air Bike 30s Sprint Test:** Flat column design for fixed 7s/14s/27s time points (not JSONB). Two sprints max, replace-all semantics on sprint updates. Sprint 2 percentages reference Sprint 1 peak power. Decay analysis: within-sprint and between-sprint comparisons
55. **Air Bike chart:** ComposedChart with Line + Scatter for Sprint 1 (cyan) and Sprint 2 (amber) power decay curves. Summary below chart with max power, W/kg, and drop-off %
56. **Coach-Athlete relationship:** Invitation-based linking (8-char codes, 7-day expiry). `athletes.user_id` column links athlete record to auth user. Centralized access control via `verify_athlete_access()` and `require_coach_or_admin()`
57. **Athlete training logging:** Athletes self-log sessions (RPE/duration hidden on log form, added later via edit) and wellness entries. Session status lifecycle: null (regular) -> 'assigned' (coach-created) -> 'completed' (athlete-finished). `created_by` column tracks session creator
58. **Session assignment flow:** Coaches create sessions with `status='assigned'` (RPE/duration omitted). Athletes complete by PATCH with RPE/duration, auto-sets `status='completed'`. Athletes can only delete own self-logged sessions
59. **Athlete exercise editing:** Athletes can update only `reps` and `weight_kg` on assigned-session exercises (all other fields silently stripped). On own sessions: full exercise CRUD including "+ Add Set" (duplicates last set config). Cannot upload CSV, manage library/templates
60. **RLS defense-in-depth:** Athlete role has INSERT/UPDATE/DELETE RLS policies on training_sessions, wellness_entries, and exercise_prescriptions. Backend access control is primary enforcement
61. **Test reports:** Consolidated athlete report builder with 6 modality sections. Config mode -> Preview mode -> PDF export via `jspdf` + `html2canvas` (client-side only). Reports persist in `test_reports` table (JSONB sections/notes). Coach/admin only
62. **Security headers middleware:** Sets HSTS (production only), X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy, Permissions-Policy, and CSP on every response
63. **Environment-aware CORS:** Development allows localhost:3000 + 127.0.0.1:3000, production only allows FRONTEND_URL
64. **Strong password policy:** Pydantic `@field_validator` on both `AuthRequest` and `AthleteSignupRequest` enforces 8+ chars, 1 uppercase, 1 digit
65. **Error sanitization:** Exception handlers replaced `str(e)` with generic messages. Real errors logged server-side via `logger.exception()`
66. **Account lockout (DB-backed):** `login_attempts` table tracks failed logins per email with IP address. 5 failures in 15 minutes → 429 response. Cleared on successful login or password reset. Stale entries (>1 hour) pruned on each check. Fails open if DB unavailable
67. **GDPR consent tracking:** `user_consents` table with `consent_type` (data_processing/data_sharing/marketing). ConsentGate component blocks app until data_processing consent granted
68. **GDPR data export (right to portability):** JSON and CSV/ZIP endpoints for all athlete data. Rate limited 5/min
69. **Deletion audit trail:** `deletion_log` table records entity summaries before deletion. `audit_log` table for general security event logging
70. **Invitation sanitization:** Validate endpoint no longer returns coach_email, only athlete_first_name. Rate limit reduced to 3/min
71. **Service worker / offline fallback:** Hand-written `public/sw.js` (zero npm deps). Navigation: network-first with `/offline.html` fallback. Static assets: stale-while-revalidate. Bump `CACHE_NAME` to purge old caches
72. **Forgot password:** Supabase `reset_password_email()` sends link to `/reset-password`. Always returns 200 (no email enumeration). Rate limited 3/min
73. **Reset password:** Token extracted from URL hash fragment. Hash cleared via `replaceState`. Token validated via `get_user()`, password updated via admin API. Forces re-login
74. **Change password/email:** Authenticated endpoints requiring current password verification. Fresh `create_client()` for each operation. Email changes update both auth and profiles table
75. **Settings page:** `/settings` — utility page (not in NAV_ITEMS), accessible via gear icon. Change password and change email sections
76. **Conditioning exercise fields:** `intensity_type` (rpe/speed_kmh/power_watts), `intensity_value`, `rest_between_reps_seconds`, `duration_seconds` on prescriptions, library, and templates. Category-aware forms
77. **Interval timer:** Full-screen overlay via `createPortal`. State machine hook with phases: idle->warmup->countdown->work->rest->complete. Wall-clock timing via `requestAnimationFrame`. Auto-pause on tab hidden
78. **Timer audio:** Web Audio API (`OscillatorNode`, zero npm deps). Countdown beeps at 3-2-1. Transition beeps at phase changes
79. **Timer save flow:** On complete, RPE slider + auto-calculated duration. PATCH session via `trainingApi.updateSession()`
80. **Per-rep durations:** `rep_durations` JSONB column on prescriptions, library, and templates. Pydantic validators: non-empty, values 1-3600, length must match `reps`
81. **Copy Set:** ConditioningExerciseForm "Copy Set" button duplicates set config including per-rep durations
82. **Per-set rest:** `restBetweenSetsArr` replaces global `restBetweenSets`. Array of length `sets.length - 1`
83. **Timer per-set data:** `TimerExercise.sets` changed from `number` to `TimerSetConfig[]` with per-set reps, duration, rest, and optional `rep_durations`
84. **Session invalidation on credential change:** `change_password`, `change_email`, `reset_password`, and `logout` all call `admin.sign_out(user_id)` to invalidate all refresh tokens globally. Cookie cleared server-side. Frontend redirects to `/login` after password/email change
85. **Role fallback 503:** `get_current_user()` raises 503 if profile DB lookup fails (instead of silently defaulting to "coach"). Prevents privilege escalation for athletes during Supabase outages. Intentional security-over-availability tradeoff
86. **Mass delete password verification:** `DELETE /athletes/` requires `current_password` in request body. Password verified via `sign_in_with_password()`. Rate limited 1/min. Audit logged before deletion
87. **24-hour cookie expiry:** `COOKIE_MAX_AGE` reduced from 7 days to 24 hours for shorter session windows
88. **Athlete UX flow audit:** Post-signup redirects to `/dashboard` (not `/testing`). Unlinked athlete error state replaces infinite spinner. RPE/duration fields shown on athlete session log form. Session badges: "Logged" (self-logged), "Overdue" (past-date assigned). Calendar view shows Complete/Add RPE buttons. Athlete-specific help section. Dismissible welcome banner on dashboard. Export failure feedback toast
89. **Coach UX flow audit:** Athlete selection persisted in localStorage across refreshes. "From Template" quick-create button on training page (opens `TemplateSessionModal`). Color-coded ACWR/HI values in ReadinessIndicator. Batch-assign notification hint. Template conflict warning. Wellness duplicate-date warning. Report data source failure banner. Athlete profile quick stats (sessions, tests, wellness count). VBT predict quick-access button. Timer icon on conditioning exercise rows
90. **Admin UX flow audit:** Upload "View Testing" goes to `/testing` (not `/`). Admin onboarding wizard enabled (`isCoachOrAdmin`). Help page title role-neutral ("User Manual"). Coaches can access Upload page (nav + page guard). Empty athlete selector is clickable CTA. Database Analysis non-admin redirect goes to `/training` (not `/dashboard`)
91. **AthleteContext localStorage persistence:** Selected athlete ID stored in `bsams-selected-athlete` localStorage key. Restored on mount if athlete still exists in list. Prevents "Select an athlete" flash on refresh
92. **TemplateSessionModal:** One-click session creation from template — picks template, creates session with today's date + template training type, applies template exercises, shows success toast. Accessible from "From Template" button on training page
93. **Cookie policy & banner:** Informational CookieBanner (not consent gate) — UK PECR Regulation 6(4) exemption for strictly necessary cookies. Dismiss persisted in `bsams-cookie-consent` localStorage key. `/cookies` page documents auth cookie, 7 localStorage keys, service worker cache. Zero third-party cookies. Privacy policy cross-references cookie policy (section 3). Footer link added between Privacy Policy and Terms of Service
94. **Training Program Marketplace:** Install=access model (not copy). `program_packages` + `program_templates` (JSONB exercises) + `program_installations` (UNIQUE user+program). Admin-authored programs browseable by all roles. `installed-templates` endpoint returns templates from installed programs for TemplateSessionModal integration. Apply flow reuses set-expansion logic from session_templates. `require_admin()` guard for program CRUD. Programs nav item visible to all roles
95. **Assault Bike BLE integration:** FTMS Indoor Bike Data protocol (service 0x1826, char 0x2AD2) with Web Bluetooth API. Two new tables: `air_bike_recordings` (standard captures with JSONB samples + computed summary stats) and `metabolic_profiles` (3-sprint Ferretti/di Prampero protocol). Air Bike tab split into 3 sub-tabs: Sprint Tests / BLE Recordings / Metabolic Profiles
96. **FTMS BLE parser:** Little-endian bit field parsing. Bit 0 inverted for speed presence. Parses: instantaneous speed, cadence, power, distance, calories, elapsed time. Frontend-only — no backend BLE dependency
97. **Metabolic profiling protocol:** 14-state machine (INACTIVE→SETUP→WARMUP→COUNTDOWN_1→SPRINT_1→REST_1→...→POST_TEST→RESULTS, plus SPRINT_ENTRY for manual). Sprint durations: 10/20/30s. Rest: 6min/15min. Post-test: 3min countdown before final lactate. Full-screen overlay via `createPortal` (z-[100])
98. **10-second analysis window:** Each sprint analyzes exactly 10s of data regardless of sprint duration. Sprint 2 uses samples 10-20s, Sprint 3 uses 20-30s. Manual mode: avg_power * 10 = mech_work_J. This is the Ferretti protocol design for comparable windows
99. **Metabolic engine dual calc:** TypeScript `metabolicEngine.ts` mirrors Python `metabolic_engine.py` (like lactateAnalysis.ts/lactate_engine.py pattern). Constants: BETA=63, ETA=0.25, TAU=15. Baseline correction: Sprint 2 base = la_peak_1 * 0.871, Sprint 3 base = la_peak_2 * 0.574
100. **Unclamped storage, clamped display:** Metabolic values (alactic capacity, energy breakdown) stored unclamped in DB — can be negative. `Math.max(0, value)` applied only in chart rendering. Insights use raw values for thresholds
101. **BLE recordings immutable:** No PATCH endpoint for recordings — captures are read-only after save. Metabolic profiles support PATCH for trim adjustments (BLE only, 400 on manual) and notes
102. **Manual entry fallback:** Metabolic profiling works without BLE — enter 3 avg power values + 3 lactate peaks manually. Firefox/Safari fully functional. `BleCompatibilityGate` component checks `navigator.bluetooth` (truthy check)
103. **Web Audio beeps:** Extended `useTimerAudio` with `playGoBeep` (1200Hz/250ms) and `playStopBeep` (400Hz/300ms) for sprint start/end. Countdown beeps at 3-2-1
104. **Screen wake lock:** `useWakeLock` hook acquires Wake Lock API during active protocol phases (countdown through post-test), releases on results/exit. Silent fallback for unsupported browsers
105. **Training blocks:** Multi-week program builder with `training_blocks` + `block_sessions` (JSONB exercises). Coaches define blocks once, apply to multiple athletes. Percentage-based loading (`percent_1rm`) auto-resolves to absolute weights via VBT profiles first, then `athlete_maxes` table fallback. Block apply reuses batch session creation + set expansion patterns. Start date must be Monday (ISO weekday validated at schema level). Sessions chunked at 500 rows for bulk insert. `block_applications` audit trail
106. **Block engine resolution:** `block_engine.resolve_percent_1rm()` checks VBT profile for athlete+exercise via `vbt_engine.build_analysis()`, falls back to `athlete_maxes` manual entries, returns "missing" if neither exists. `round_to_plate(kg, 2.5)` rounds to nearest plate increment
107. **Exercise video URLs:** `video_url TEXT` on `exercise_library`. Play icon (&#9654;) in ExerciseAutocomplete opens URL in new tab. Video URL input in ExerciseLibraryFormModal
108. **Conditioning templates:** Gold-standard admin-owned session templates with `template_category='conditioning'` and `tier` (foundation/intermediate/advanced). Listed via `?category=conditioning` query param (skips coach_id filter). `conditioning_engine.py` resolves tier-based intensity ranges per athlete from metabolic_profiles > air_bike_recordings > air_bike_sprints. Foundation=0.4-0.6x, intermediate=0.6-0.8x, advanced=0.8-1.0x of reference power. RPE/speed use hardcoded tier defaults
109. **Intensity ranges (generic):** `intensity_min`/`intensity_max` on `exercise_prescriptions` + `BlockExercise` JSONB. Works with any `intensity_type` (power_watts, speed_kmh, rpe). Timer and ExerciseTable display range format when both set, single value fallback
110. **Template apply fix:** `apply_template` now includes `rep_durations`, `rest_between_reps`, `rep_intensity_values`, and `notes` — previously omitted. `batch_assign_sessions` similarly updated with all conditioning fields
111. **CPET gas analysis:** `gas_analysis_data` table (1:1 UNIQUE FK to lactate_tests). Excel/CSV parsing via `openpyxl` + stdlib `csv`. Flexible column aliases (MetaSoft, COSMED, Cortex). Cycling: continuous ramp, stages by work_rate_w. Running: time-boundary protocol (configurable stage/rest durations). Last-60s steady-state averaging (default). Max fat oxidation, CHO/FAT crossover, threshold interpolation. TypeScript mirror `cpetAnalysis.ts`. Chart overlay system (max 2 active, 6 available: VO2/VE/BF/FAT/CHO/EE)
112. **Combine attempts + promotion:** Combine results are logged to `combine_attempts` (every attempt, soft-voidable) and the *best* is promoted into `performance_events` / `vbt_profiles` / `air_bike_tests` tagged `combine_event_id`. Writing every attempt straight into `performance_events` would weight `analysis.py` cohort benchmarks by attempt count, so a partial unique index `(athlete_id, event_date, combine_event_id) WHERE combine_event_id IS NOT NULL` enforces exactly one row per athlete per combine. Hot path merges one station's keys atomically via the `combine_upsert_event_metrics` RPC (two workers, two stations, same athlete); void/sync rebuilds the row so a fully-voided station is cleared. `POST /combine/events/{id}/sync` re-promotes idempotently.
113. **Combine public share token:** `GET /combine/public/{token}` is unauthenticated — `secrets.token_urlsafe(24)` (24 random bytes, 192 bits), expires at event_date + 2 days, rotatable and revocable. Unknown / expired / revoked / draft / consent-not-confirmed all return a byte-identical 404. Payload is built from explicit field literals (never `**row`): no athlete/participant ids, DOB, gender, body mass, club when hidden, or numeric `z_bs`. Backend holds the service_role key so RLS protects nothing here; the sanitisation is the security boundary. Going live requires `public_display_consent_confirmed_at` — participants are usually minors.
114. **Combine benchmark bands, not z-scores:** the public board shows `bs_band` (elite/above_average/average/developing), never a numeric benchmark z — a z published beside the raw value for 40 athletes lets anyone solve for the Boxing Science mean and SD. Air bike is published as W/kg only for the same reason (W plus W/kg makes body mass derivable). Norms come from `bs_norms_snapshot` written onto the event row by the admin-only `refresh-norms` endpoint, so the public request never reaches `admin_pool`; the event's own participants are excluded from the pool, and bands need n >= 20.
115. **Air bike split schemes:** `air_bike_tests.split_scheme` (`7_14_27` | `7_17_27`, defaulting to the original) plus a nullable `air_bike_sprints.power_17s`; `power_14s` dropped `NOT NULL` with a CHECK that one mid split is present. Schema-level validator requires exactly one mid split and one scheme per test. `list_tests` max-power now skips NULLs (it would have raised `TypeError`), and the frontend reads splits through `lib/airBikeSplits.ts` rather than touching `power_14s` directly.
116. **Combine kiosk:** public board at `/combine/live/[token]`, polled every 5s with `If-None-Match` (there is no WebSocket/SSE anywhere and the CSP has no `wss:`). `AppChrome` hides the header/gutters/footer/cookie banner on that route via `usePathname`, avoiding the header flash the `createPortal` pattern has. The last-good payload survives network errors, 429 and 5xx — a blip must not wipe the wall — but three consecutive 404s blank it, because 404 is what revoke, rotate and expiry all answer and "Turn off" has to take names off a TV that is already on. Staleness surfaces as RECONNECTING at 20s and OFFLINE at 120s. Type is vh-relative (`text-[5vh]` headings, `text-[7vh]` values) so one board suits a 55" TV and a 27" monitor. Dot-plot jitter is derived from the bib so dots do not jump on each poll; `isAnimationActive={false}` throughout. Public rate limit is keyed on the share token, not the client address — every device reaches the API through the same proxy.
117. **Login on a throwaway Supabase client:** `login`, `signup` and `signup_athlete` call `sign_in_with_password`/`sign_up` on a fresh `create_client(...)` with `auto_refresh_token=False, persist_session=False`, never the service-role singleton. The installed `supabase` 2.27.3 swaps a client's `Authorization` header to the signed-in user's token, so logging in on the shared client left every later query on that worker running as the last person to log in, under their RLS. On an event day that turns station saves into "Combine event not found" and 404s the board. The singleton still does all DB work.
118. **RFD unit per event:** `combine_events.rfd_unit` (`n_s` | `kg_s`) records what the dynamometers at that event read. Values are always *stored* in N/s — the metric registry, engine, promotion and norms carry no unit — so `BilateralForceMeasures` converts kg/s at the API boundary (× 9.80665, 1 dp) and keeps `rfd_left_entered` / `rfd_right_entered` / `rfd_unit_entered` for provenance. Ranges are checked **after** conversion, so 2100 kg/s is rejected as 20594 N/s. `rfd_unit` is input-only (`Field(exclude=True)`): an N/s attempt stores exactly the keys it always did. The conversion is idempotent, guarded on `rfd_unit_entered`.
119. **Strict weight categories:** the 20 England Boxing categories live in `WEIGHT_CATEGORIES` (`schemas/combine.py`), mirrored in `lib/combineParticipantForm.ts` in identical order, with a Jest test keeping them in step. `normalise_weight_category` / `normaliseWeightCategory` accept `57`, `57 kg`, `57KG`, `91+`, `+91`, `91kg+` and return None for anything else. `ParticipantUpdate` 422s an unknown value (blank clears to NULL); `RosterRow` stays permissive on purpose so the bulk import reports one bad line as a row error instead of 422-ing the whole paste.
120. **Landmine both sides:** attempts carry `side` (`left`/`right`), the board ranks the best of either and shows `L`/`R`, and promotion writes one VBT profile per side — `"<exercise> (Left)"` / `"<exercise> (Right)"` — with the bare name kept only for legacy no-side attempts. Ranking uses the event's configured velocity metric with **no** peak↔mean fallback, so the router 422s a throw missing it rather than letting it save, promote nothing and go missing until the end of the day. Norms pool the bare name and both suffixes, one best per athlete across sides.
121. **Promotion writes only what it owns:** `_promote_air_bike` and `_promote_landmine` scope every lookup and delete to `combine_event_id`, not athlete + date — without it any combine save or void overwrote a *manual* same-day air bike test or VBT profile. The hot path is station-scoped (`submit_attempt` passes `station` down, merging just that station's keys through the RPC), while voids, corrections and sync keep the full rebuild, which is the only thing that can clear a fully-voided station. Each target gets its own `try`; a `23505` is logged and skipped rather than counted as failed, and `promote_event` returns a participant failure count surfaced as `sync_event`'s `unsynced_count`. The bands those promoted rows are scored against are decision 122.
122. **Gender-matched bands, and only on the leader:** `bs_norms_snapshot` carries `by_gender` beside the pooled aggregate and the engine scores each boxer against their own gender's norm — one pooled, mostly-male norm had a strong 16-year-old girl reading DEVELOPING, in red, on a public wall. A missing gender, a missing gender entry, or n < 20 yields **no** band and never falls back to the pooled norm, so a pre-fix snapshot shows nothing until an admin presses "Refresh Boxing Science bands"; `bs_norms_coverage` reports n per key per gender (counts only, never means or SDs) so the console can name the thin ones. On the public payload only rank 1 is banded: a band beside every raw value lets the four fixed thresholds bracket the very mean and SD the band exists to hide. `airbike_score_basis` is `w_per_kg` only — `absolute_w` scored raw watts against a W/kg norm, which put every boxer in the top band and labelled watts "W/kg".
123. **Public board withdrawal and hidden fields:** hiding club names drops `?club=` before the filters, the ETag and the cache key — a filter that still worked would enumerate the hidden club membership of named minors one club at a time. The kiosk counts consecutive 404s and blanks the board after three, resetting on any 200 or 304: revoke, rotate and expiry all answer 404, so without it "Turn off" never took names off a TV that was already on. Network errors, 429 and 5xx keep the last good payload, and an abort caused by a newer poll is not a failure. The 304 carries `Cache-Control: no-cache` next to the `ETag`, or a proxy answers the next poll from its own copy and the board stops noticing results.
124. **Reads paginated past PostgREST's row cap:** an unpaginated select stops at the project's `db-max-rows` (1000 by default) with no error, and a short result looks exactly like the whole result. `fetch_all_rows(build_query, page_size=1000)` in `combine_norms.py` builds a fresh query per page, `.order("id").range(...)`, stopping on a short page. Used for the attempt log (40 boxers throwing both landmine sides reach ~1,080 attempts, and the board would silently drop results), for the norms pool inside `_chunked_in`, and for the roster import's athlete-name lookup — an admin can own more than 1000 athletes, which would make the duplicate preview wrong.
125. **Selectable Combine Score basis:** `combine_events.overall_score_basis` (`z` | `percentile`, migration 035) chooses what `combine_score` carries on each overall entry — the T-score `50 + 10 * mean(z)`, or `percentile_score`, the mean of a boxer's per-station percentiles to 1 dp. `station_percentiles` is pure and left unrounded, because it is working state and only the composite it feeds is published (the same reason `cohort_z` is rounded at the row): each boxer's share of the rest of the displayed cohort they beat, ties taking the midpoint of the positions they span, a lone boxer 50.0. **The default is `z`, and the read is deliberately tolerant** — `overall_basis()` maps a missing column, a NULL and an unrecognised value all to `z`, so a row written before the migration scores the way the room was briefed, and the code is safe to deploy either side of the SQL. The first real event is run on the number coaches and boxers have already been told about; a scoring change nobody asked for is a change to the result, not to the presentation. That is what the two frozen fingerprints in `test_combine_engine.py` guard: taken from the engine before this option existed, they assert a default event's authenticated and public boards byte-for-byte. On 119 athletes of the project's own historical data the two orders agree at Spearman 0.982 with 8 of the top 10 shared, so this is a presentation choice rather than a correction — percentiles earn their place on skewed metrics, where contact time clears z >= 1.0 for only 1.7% of athletes against normal theory's 15.9%, and in explaining the number to a 15-year-old. They cost margin (dominating a station scores the same as edging it) and coarsen the scale to roughly 2.5 points a place at 40 boxers, so ties get more common. Eligibility, competition ranking and the `(rank, bib, display_name)` tie order are untouched, `mean_z` stays authenticated-only and keeps meaning mean z, and `build_leaderboard` returns a top-level `score_basis` — declared on both `LeaderboardResponse` and `PublicLeaderboardResponse` — so the board captions the number instead of asserting "50 is the room average" beside a percentile. The authenticated event read is `select("*")` and picks the new column up for free; the public board's read is an explicit column literal (decision 113), so `overall_score_basis` is named there too — without it the wall keeps scoring on z while the console switches. The shared `FakeSupabase` returns whole rows whatever the select list says, so an ordinary test cannot catch that omission: `ProjectingStore` in `test_combine_public.py` subclasses it to honour a column list the way PostgREST does, and holds this one read to it. The public payload gained a top-level key, so `PAYLOAD_SCHEMA_VERSION` goes to 2 — an ETag is a promise about a payload shape, and a kiosk holding one from before the deploy would otherwise be answered 304 and keep a board with no `score_basis` in it until the next result landed.
